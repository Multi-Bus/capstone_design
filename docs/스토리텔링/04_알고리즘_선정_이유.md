# 알고리즘 선정 이유

슬라이드 3, 9의 근거다. 수치는 파이썬 학습용 시뮬(이상적 조건)이며 실기체 성능이 아니다.

## 1. 선정 요약

| 역할 | 선정 | 비교군 | 한 줄 이유 |
| --- | --- | --- | --- |
| 충돌 회피 | **CBF-QP 안전 필터** | APF, ORCA, MPC / TinyMPC | 안전을 조건으로 보장하고, 위험할 때만 최소 수정 |
| 편대 | **Consensus** (기본) | Leader-Follower, Virtual Structure | 중앙 조율자 없음, 일부 통신 단절에도 동작 |
| 구조 | 편대 `v_nom` → 안전 필터 `v_safe` | | 안전 > 편대 > 목표 도달 우선순위 |
| 경량화 | **이벤트 트리거 통신** | 20 Hz 주기 방송, 중앙 우선순위 | 지도교수 추천, 실기체 6대에서 실제로 줄일 수 있는 것 |
| 3D | CBF (차원 무관) | ORCA는 2D 전용 | 드론은 3차원 이동 |

## 2. 왜 CBF-QP인가

### 이야기 순서

1. **APF**: 가장 단순(힘의 합, 30줄). 그러나 지역최소점에 갇히고 상대의 움직임을 모른다. 장애물 · 목표가 일직선이면 x = 4.22에서 정지 재현. 계수 튜닝도 까다롭다.
2. **CBF와 ORCA**: 둘 다 "제약을 만족하는 `v_nom`에 가장 가까운 속도"라는 같은 구조. 이웃마다 반공간 하나를 만든다. 차이는 제약을 만드는 방식뿐: CBF는 거리 함수 `h = ‖Δp‖² - D²`의 변화율, ORCA는 속도 공간의 원뿔(VO) 경계를 직선으로 근사.
3. **차이를 가른 것**: 지연이 들어올 때.

| 비교 항목 | APF | CBF | ORCA |
| --- | --- | --- | --- |
| 차원 | 2D / 3D | 2D / 3D (같은 코드) | 2D 전용 (3D는 구성이 복잡) |
| 이웃 속도 | 불필요 | 필요 | 필요 |
| 안전 조건 | 암묵적 | **명시적 (QP 제약)** | 명시적 (반평면) |
| 이상적 조건 최소 이격 | 0.416 m | 0.469 m (2D), 0.485 m (3D) | 0.400 m (안전거리에 딱 닿음) |
| 도달 시간 | 8.9 s | 10.7 s (2D), 9.25 s (3D) | 7.7 s |
| 속도 추종 지연 τ 반응 | | τ = 1.0 s에서도 최소 이격 0.406 m | τ ≥ 0.5 s에서 안전거리 침범 |
| 교착 | 지역최소점 | 해 없으면 정지 | 밀집 시 모두 정지 |
| 편대 결합 | 어려움 | **필터 구조에 자연스러움** | 가능 |

### 선택 이유

- **편대 제어와 합치기 좋다.** 편대는 "모여라", 회피는 "흩어져라"라 단순 평균은 어중간해 위험하다. CBF는 위험하지 않으면 제약이 느슨해 `v_nom`이 그대로 통과하고, 위험할 때만 최소 수정하므로 "편대 속도를 쓰다가 위험할 때만 고치는" 구조에 맞는다.
- **3D를 그대로 쓴다.** 코드 변경 없이 3차원.
- **여유를 설정할 수 있다.** 안전거리에 오차 상한(`D_eff`)을 더하는 방식이라 불확실성을 정량화하기 쉽다. ORCA는 안전거리에 딱 맞춰 회피해서 지연에 취약했다.
- **임베디드 가능성.** QP는 이웃 수에 비례하는 소규모 문제다. N6에서의 실제 시간은 Task 3 Lv3에서 측정한다.
- **교수 의견.** "MPC/CBF로 해결 안 된 경우는 별로 없다"(미팅 자막 기반이라 요지만 옮김), CBF/APF와 AI 결합 비교군도 승인.

### 한계

- CBF는 안전을 보장하지만 진척은 보장하지 않는다. 멈출 수 있다(교착).
- 속도 명령이 즉시 실현된다고 가정한다. τ는 `D_eff`와 `v_max`로 보상한다.
- 이웃의 위치 · 속도를 알아야 한다. 통신 의존이다.

## 3. 비교군을 두는 이유

| 비교군 | 이유 |
| --- | --- |
| APF | 가장 가벼운 기준선. 계산 시간 하한 |
| ORCA | 표준 속도 장애물 방식. 지연 취약성 확인 |
| MPC / TinyMPC | 지도교수 지정 참고. "무거운 방법(MPC)을 가볍게 만든 사례 vs 우리가 가볍게 만든 방법" 대비. TinyMPC가 다중 드론 회피를 직접 다루는지는 확인 못 함 |
| 학습 기반(GCBF+ 등) | 지도교수가 허용한 범위. `v_nom`을 학습하고 안전은 고전 CBF가 보장하는 구조(AI-2)가 안전 |

## 4. 왜 Consensus 편대인가

| 방식 | 장점 | 약점 |
| --- | --- | --- |
| Leader-Follower | 구현 가장 쉬움 | 리더 고장 시 붕괴 |
| Virtual Structure | 회전 · 형태 변경 유리 | 모두 같은 기준점을 알아야 함 |
| **Consensus** | 중앙 조율자 없음, 일부 통신 단절에도 동작, 현재 주류 | 수렴 속도가 연결 구조에 좌우 |

시뮬(6대 화살촉 대형, 30초): 최종 편대 오차 약 4 ~ 5 cm로 수렴. 이웃 수를 줄이면 통신이 줄지만 수렴이 느려지는 **경량화 트레이드오프**가 생긴다. 지도교수는 회피가 먼저이고 편대는 그 다음이라고 순서를 두었다.

## 5. 왜 이벤트 트리거인가

### 경량화 5축 평가

| 축 | 지도교수 반응 | 판단 |
| --- | --- | --- |
| A. 알고리즘 대체 | 새 수식은 어려움, 기존 CBF/APF 사용 OK | 비교군으로만 |
| B. 이웃 수 축소 | 직접 언급 없음 | 6대에선 효과 거의 없어 시뮬 확장성만 |
| C. 연산 단순화 | 대학원 수준 | 쉬운 것만 |
| D. 하드웨어 가속 | "만들어 보고 해야겠지" | 보류 |
| **E. 통신 · 실행 빈도 축소** | **"가장 유명하니 추천. 언제 위치 정보를 주고받아야 하는지 조건 연구"** | **주력** |

### 근거

- 수신 측이 외삽으로 이미 정확히 예측하면 매번 보낼 필요가 없다. 예측 오차가 δ를 넘거나 T_max가 지나면 보낸다.
- 시뮬: 60초 비행에서 50 Hz 3000회 → 61회(약 98% 감소), 최대 오차 0.149 m (δ = 0.15 m). 운동이 완만한 경우다.
- 선행 연구에서 통신 · 구동 50% 이상 절감, 성능 저하 미미 보고(사전조사). Event-triggered 편대 제어 arXiv 1709.06652.
- 위험과 대응: 급회피에서는 이벤트가 자주 생겨 절감이 줄 수 있다 → 실제 회피 시나리오에서 측정(E1, E2). 침묵이 링크 단절인지 예측 정확인지 구분해야 한다 → T_max. δ는 `D_eff`에 더한다.
- BLE 실측 결과: 전송 횟수를 줄여도 **연결 간격은 짧게 유지**한다. 지연이 간격에 좌우되기 때문이다.
