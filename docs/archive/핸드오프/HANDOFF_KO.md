# N6 드론 BLE 이륙 — 인수인계 (2026-11-20 기준)

처음이면 이 순서로 읽으세요.
1. **이 파일**: 어디까지 했고 무엇이 남았는지
2. **`QUICKSTART_KO.md`**: STM32(NUCLEO) 보드와 BLE를 실제로 연결하고 실행하는 순서
3. **`README_KO.md`**: 자세한 참고서 (빌드·플래시 명령, 파라미터 표, 문제 해결 표)

## 1. 한눈에 보기

- **된 것**: 노트북 → BLE → XIAO → NUCLEO → FC 명령 경로는 완성됐고, **프롭 없이** 모든 안전 기능을 시험해 통과했습니다.
  - 시동, 이륙 순서, 킬(LAND), 비상 정지, 링크가 끊겼을 때 FC가 스스로 착륙하는 것까지 확인했습니다.
- **남은 것 = 인수받는 분이 해결할 문제**: **프롭을 단 실제 비행이 아직 성공하지 못했습니다.** 6장에 증상, 숫자, 확인 순서를 정리했습니다.
  - **증상 A**: 모터가 세게 돌아도(배터리가 15.7 V에서 14.0 V까지 처짐) **기체가 바닥에서 떨어지지 않습니다**(2026-11-20 12:30).
  - **증상 B**: 바닥에 있는데 **FC 높이(EKF)만 1 m 넘게 올라갑니다.** 그래서 FC는 목표 높이를 넘었다고 보고 출력을 줄입니다.
  - 예전 시도(11-19)에서는 7~16 cm 뜨다가 한 방향으로 쏠렸습니다.
- **원인이 아닌 것으로 확인됨**: 명령 경로, 페일세이프, 모터 위치·방향, FC 장착 방향.
  - 광류 센서 방향은 **틀려 있어서 고쳤습니다**(2026-11-20, `FLOW_ORIENT_YAW` 18000). 고친 뒤에도 증상 A·B는 그대로입니다.
- **먼저 볼 것**: 프롭 장착 방향 → 배터리 만충 → **FC 로그(.bin) 분석**. 6장 "다음에 할 일" 순서대로 하세요.

## 2. 목표 (원래 작업 지시)

- 노트북에서 BLE로 명령해 **0.8 m 이륙 → 5초 호버 → 착륙**
- **킬 버튼**: 언제 눌러도 그 자리에서 LAND, 착지하면 FC가 스스로 시동을 끔
- **비상 모터 정지**(선택): 강제 시동 끔(`COMPONENT_ARM_DISARM`, 21196)
- **링크 끊김**: 어디서 끊기든 FC가 3초 뒤 스스로 LAND
  - 방법: 노트북이 지상국 HEARTBEAT(sysid 250)를 초당 5번 보내고, FC의 GCS 페일세이프가 이를 감시합니다.

## 3. 구성

```
노트북 tools/n6_fly.py (Python: bleak + pymavlink)
  ──BLE (Nordic UART Service)──>  XIAO nRF52840   (이름 N6-DRONE-1, 중계 펌웨어)
  ──USART2 115200──>              NUCLEO-N657X0-Q (nucleo/n6_bridge, 바이트를 그대로 넘기는 브리지)
  ──UART7 921600──>               FC (DAKEFPV H743, ArduPilot 4.7.x, SERIAL4 = MAVLink2)
                                    └ 광류 + 거리센서 MTF-01P (SERIAL1), GPS 없음, 실내 비행
```

- 비행 로직은 **전부 노트북 Python**에 있습니다. NUCLEO는 MAVLink를 해석하지 않고 바이트만 넘깁니다.
- 기체 정보(FC 파라미터 파일 주석 기준): 3인치 덕트, 4S 배터리. 만충은 약 16.8 V이고, 시험할 때는 15.9 V 정도였습니다.

## 5. 하드웨어에서 고친 것·알아낸 것 (중요)

1. **FC의 RX4 핀**: DAKEFPV H743의 HD VTX 커넥터 4번 핀(D/V)은 윗면 **"Dji" 점퍼 패드**(가운데 패드 ↔ Dji 패드)를 납땜해야 RX4가 됩니다.
   - 원래 패드가 열려 있어서, 노트북 → FC 명령이 하나도 들어가지 않았습니다(FC SERIAL4 RX = 0).
   - **납땜해서 해결했습니다.** 다른 기체를 만들 때도 확인하세요.
2. **XIAO는 드론 배터리를 연결해야 안정적입니다.** 캐리어의 5V만으로는 BLE가 자꾸 끊겼습니다(전압 부족으로 보임).
3. **PC 블루투스**: 개발 PC에는 내장 블루투스가 없어서 USB 동글(Realtek RTL8761BU)을 썼습니다.
   - USB 자동 절전 때문에 HCI 타임아웃이 났고, 끄고 나서 해결됐습니다(`QUICKSTART_KO.md` 5장).
4. **NUCLEO 디버깅 주의**: 브리지가 디버거 없이 돌고 있는 보드에 나중에 붙으면 CM55 코어(AP1)에 접근하지 못합니다.
   - 전원을 껐다 켜야만 풀립니다.
   - 디버그·플래시는 전원을 다시 넣은 직후에 하세요.

### 지금까지 알게 된 것

1. **원인이 아닌 것**: 명령 경로(BLE~FC), 모터 위치·방향, FC 장착 방향, 페일세이프. 광류 방향은 틀려 있어서 고쳤습니다(4장).
2. **증상 A — 세게 돌아도 안 뜸**
   - 12:30에 배터리가 1.7 V(셀당 약 3.5 V까지) 처질 만큼 전류를 썼는데 1 cm도 뜨지 않았습니다.
   - 3인치 덕트 4S 기체는 보통 출력 절반 이하에서 뜹니다(파라미터 파일의 `MOT_THST_HOVER` 0.25). 그러니 **추력이 제대로 안 나고 있을** 가능성이 큽니다.
   - 후보는 다음과 같습니다.
     - **프롭이 회전 방향과 안 맞거나 뒤집혀 끼워짐** — **아직 확인 안 함**
     - 배터리 부족 또는 노후: 시작 15.72 V(만충 16.8 V)
     - 프롭이 덕트에 닿음, 모터·ESC 문제
     - 무게가 추력에 비해 무거움
   - 또는 FC가 출력을 끝까지 안 올렸을 수 있습니다(증상 B 때문). 이 둘은 **FC 로그의 모터 출력(RCOU)**으로 구분됩니다.
3. **증상 B — 바닥에 있는데 FC 높이가 올라감**
   - 11:04에는 +1.42 m, 12:30에는 +1.35 m까지 올라갔습니다. FC는 목표를 넘었다고 보고 출력을 줄입니다.
   - 후보는 셋입니다.
     - 진동(가속도계)
     - 프롭 바람으로 흔들린 기압계
     - `EK3_RNG_USE_HGT`가 기압계로 전환됨. 낮게 있을 때 거리센서를 쓰다가, EKF 수평 속도 추정이 2 m/s(`EK3_RNG_USE_SPD`)를 넘으면 기압계로 돌아갑니다.
   - 12:30에는 **시동 전부터** FC 높이가 −0.27 m(거리센서 0.02 m)로 어긋나 있었습니다.
     - 재부팅 뒤 광류 시험으로 손에 들었다 내린 탓으로 보입니다.
     - → **비행 직전에는 바닥에서 재부팅하고, 그 뒤에는 들지 마세요.** 상태줄에서 `EKF높이`가 거리센서와 0.1 m 안인지 확인합니다.
   - 이렇게 생긴 오차는 재부팅 전까지 남습니다. 착지 후 +0.8~1.0 m가 그대로 남는 이유입니다.
4. **쏠림**: 광류를 고친 뒤에는 뜨지 않아서 아직 판단할 수 없습니다.
5. **킬·LAND 뒤 시동 꺼짐**: 12:30에는 4.3초로 정상이었습니다. 11:04에는 32초가 걸려 `x x`로 껐습니다. **바닥에 내려앉았는데 5초 넘게 안 꺼지면 `x x`**를 쓰세요.

### 다음에 할 일 (순서대로)

1. **프롭 확인** (배터리 뺀 상태)
   - 위에서 볼 때 **A(앞오른쪽)·C(뒤왼쪽)는 반시계용, B(뒤오른쪽)·D(앞왼쪽)는 시계용**이어야 합니다. 앞은 FC 화살표의 반대쪽입니다.
   - 뒤집혀 있지 않은지 봅니다. 회전 방향으로 **두껍고 높은 날(앞전)이 먼저** 지나가야 합니다.
   - 손으로 돌려서 덕트에 닿거나 걸리지 않는지 봅니다.
2. **배터리 만충**(16.8 V 근처) 뒤에 시험합니다.
3. **FC 로그(.bin) 분석** — 가장 확실합니다.
   - FC USB를 PC에 꽂고 **QGC → Analyze Tools → Log Download**에서 **11-20 12:30**(그리고 11:04, 11-19 23:29) 로그를 받습니다.
   - 내용 보기: `mavlogdump.py --types RCOU,CTUN,VIBE,RFND,MOTB <파일>.bin` (pymavlink에 들어 있음) 또는 MAVExplorer

   | 메시지 | 볼 것 |
   |---|---|
   | `RCOU` | 모터 4개 출력. **최대 근처에 붙었는데 안 떴으면** 추력 문제(프롭·배터리·무게). **중간에서 멈췄으면** FC가 높이를 잘못 알아서 안 올린 것(증상 B) |
   | `CTUN` | `ThO`(출력), `ThH`(호버 추정), `Alt`(FC 높이) vs `DAlt`(목표), `BAlt`(기압계) |

   | `RFND` | 거리센서 |
   | `XKF4`, `XKF5` | EKF 높이 쪽 혁신값(innovation), 상태 |

   - 바닥에서 재부팅합니다.
   - **프롭 없이** `python dev/height_check.py`를 실행하고 바닥 → 손으로 0.3~0.5 m → 바닥 순서로 움직입니다. 정상이면 FC 높이 ≈ 거리센서 − 0.05 m입니다.
   - 그다음 바닥에서 다시 재부팅합니다.
   - FC 설정 파일(9장)에도 반영합니다.
   - 주의: 기체 아래에 물건이나 늘어진 안전줄이 있으면 높이 값이 바뀝니다.
5. **파라미터 확인** (BLE, 읽기만):
   ```bash
   python dev/param_read.py MOT_THST_HOVER MOT_SPIN_ARM MOT_SPIN_MIN MOT_THST_EXPO TKOFF_THR_MAX EK3_SRC1_POSZ EK3_RNG_USE_HGT
   ```
6. **무게 중심 확인**: 배터리를 장착한 채 기체 중앙을 손가락으로 받쳐 봅니다.
7. **비행 시험** (프롭 + 안전줄, 0.5 m)
   - **바닥에서 재부팅 → 그 뒤 들지 않기 → 상태줄에서 `EKF높이`가 거리센서와 0.1 m 안인지 확인** → `t` → `y`
   - 안전줄은 기체 위 중앙에 묶고, 바닥에 늘어지지 않게 합니다.
8. (선택) **스크립트 개선** (`tools/n6_fly.py`, 고친 뒤 `python dev/sim_test.py` 통과 확인):
   - `t`를 누르기 전에 바닥에서 EKF 높이와 거리센서가 0.15 m 넘게 다르면 이륙을 막기
   - 이륙 중 거리센서가 계속 바닥이면 3초 호버 없이 바로 LAND
   - 킬 후 바닥에서 5초 넘게 시동이 안 꺼지면 `x x` 안내
9. (선택) **XIAO v2 펌웨어 올리기**: FC → 노트북 손실을 줄입니다(`QUICKSTART_KO.md` 6장).
10. (참고, 완료) **광류 센서 방향**: `python dev/flow_check.py`로 확인합니다. 손으로 들고 제자리에서 좌우·앞뒤로 기울이면 됩니다. drone1은 180° 어긋나 있어서 18000으로 고쳤고, 재시험에서 상관 +0.99/+0.88이 나왔습니다. **다른 기체도 꼭 확인하세요.**

## 7. 안전 규칙 (지금까지 지킨 것)

- **보드에 플래시하거나 모터가 돌 수 있는 명령(시동·이륙·모터 시험)은 실행 전에 팀에 먼저 알리고 하세요.**
- 새 기능이나 설정 변경 뒤 첫 시험은 **항상 프롭을 떼고** 합니다. 프롭 단 비행은 **안전줄**을 묶고, 사람은 떨어져 있습니다.
- 스위치·점퍼는 **전원을 끈 상태에서** 바꿉니다.
- **킬 = 스페이스**(그 자리 LAND)를 먼저 씁니다. `x x`(강제 정지)는 **공중이면 추락**하니 바닥에서, 또는 정말 위험할 때만 씁니다.
- XIAO는 **BLE 연결을 하나만** 받습니다. `n6_fly.py`, `dev/*.py`, 휴대폰 앱을 동시에 연결하지 마세요.
- `FS_GCS_TIMEOUT`은 **3초 기준**입니다. 스크립트도 3초를 기준으로 경고합니다.
