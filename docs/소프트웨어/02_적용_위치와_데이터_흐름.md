# 적용 위치와 데이터 흐름

[알고리즘 목록](01_알고리즘_목록.md)의 알고리즘이 어느 장치 · 모듈에서 돌고 어떤 값을 주고받는지 정리한다. 센서 쪽은 [입출력 연결](../하드웨어/03_입출력_연결.md)에 있다.

## 1. 장치별 역할

| 장치 | 실행하는 것 | 메모 |
| --- | --- | --- |
| FC (H743, ArduPilot 쪽) | EKF, 속도 · 자세 · 각속도 루프, MTF-01 처리, (보조) ToF 근접 회피 | 펌웨어 확정 여부 확인 필요 |
| N6 (NUCLEO-N657X0-Q) | 위치 추정, 이웃 상태, 장애물, 편대 제어, CBF-QP, MAVLink, 기록 | Linux 없음. RTOS 또는 베어메탈 |
| XIAO nRF52840 | BLE 송수신 | N6와 UART 가정 |
| PC + 동글 | 로그 수집, 목표 배포, 시계 비콘, (2홉 시) 중계 | |
| UWB 앵커 | TWR 응답 | 소프트웨어 직접 빌드 필요 [미확인] |

## 2. 데이터 흐름 (N6 기준)

```
[1 내 상태]  UWB 거리 3개 → 수평거리 환산 → 이상치 제거 → 3점 위치 → 월드→NED → ODOMETRY(MAVLink2) → FC
             FC EKF(UWB 위치 + 광류 속도 + IMU) → 융합된 p, v, 자세를 N6로 회신
[2 이웃]     BLE 패킷(id, t_tx, p, v, seq) → 순번 검사 → 시계 보정 → 외삽 → AoI · stale 판정
[3 장애물]   ToF ×5 → 필터 → 몸체→월드 변환 → 이웃과 중복 제거 → 장애물 점
[4 편대]     v_nom = v_ref + Σ k_c ((p_j - p_i) - (오프셋_j - 오프셋_i))
[5 CBF-QP]   이웃별 D_eff, 장애물별 D_obs, |v| ≤ v_max 제약 → v_safe  (해 없으면 감속 · 정지)
[6 명령]     v_safe(NED) → SET_POSITION_TARGET_LOCAL_NED, 20 ~ 50 Hz (끊기면 3 s 뒤 정지)
[7 기록]     SD + 동글 텔레메트리 → E1 ~ E6 지표
```

## 3. 모듈 책임

| 모듈 | 입력 | 출력 |
| --- | --- | --- |
| 위치 추정 | UWB 거리, MTF-01 고도 | ODOMETRY (공분산 포함) |
| 이웃 상태 | BLE 패킷 | 이웃별 `p̂_j`, `v̂_j`, AoI, stale |
| 장애물 | ToF 거리, FC 자세 | 장애물 점 |
| 편대 제어 | `p_i`, `p̂_j`, 역할 ID | `v_nom` |
| 안전 필터 (CBF-QP) | `v_nom`, 이웃, 장애물 | `v_safe` |
| FC 인터페이스 | `v_safe` | MAVLink 속도 명령 |
| 송신 판단 (이벤트 트리거) | 내 상태, 마지막 송신 값 | 전송 여부 |
| 기록 | 전 모듈 | SD 로그 (송수신 타임스탬프 포함) |

인터페이스는 `v_nom → v_safe` 함수 하나로 편대 제어와 안전 필터를 분리한다. 회피 알고리즘을 바꿔 끼우려면 이 경계를 지킨다.

## 4. CBF-QP 정의

원하는 속도 `v_nom`을 먼저 정하고, 이웃마다 안전 조건을 만든 뒤 모두 만족하는 속도 중 `v_nom`에 가장 가까운 것을 고른다.

```
min ‖v - v_nom‖²   s.t.   a_j · v ≥ b_j  (이웃 · 장애물마다),   ‖v‖ ≤ v_max
h_ij = ‖p_i - p_j‖² - D_eff²,   ḣ ≥ -γ·h     →   a_j = p_i - p_j,  b_j = (p_i - p_j)·v_j - ½γ·h
```

- 멀리 있으면 제약이 느슨해 `v_nom`이 그대로 통과하고, 위험할 때만 최소 수정한다.
- 이웃 속도 `v_j`가 필요하다. 통신 지연은 `D_eff`로 흡수한다([안전 여유](../설계/03_안전여유와_실험설계.md)).
- 제약을 만족하는 해가 없을 수 있다(사방이 막힘). 이때 감속 · 정지하고, 교착으로 이어지는지 지표로 센다.
- 속도 명령이 즉시 실현된다고 가정한다. 실제로는 τ만큼 늦어서 `D_eff`와 `v_max`로 보상한다.

## 5. 규칙과 설정값

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 우선순위 | 안전 > 편대 유지 > 목표 도달 | |
| 위치 필터 | 이동평균 사용 안 함 | 3점 평균은 20 Hz에서 50 ms 지연. 평활은 FC EKF에 맡김 |
| 이웃 패킷 | 64 B × 50 Hz (BLE 실측 요구치) | 구설계 31 B × 20 Hz는 팀 합의로 통일 필요 |
| 방송 기준선 | 20 Hz 주기 방송 | 이벤트 트리거와 비교 |
| N6 ↔ FC UART | 460800 baud 이상 | 115200은 부족 (약 139 kbaud 필요) |
| 속도 명령 | 20 ~ 50 Hz | 끊기면 3 s 뒤 정지 (ArduPilot 확인) |
| 이상 상황 | stale → D_eff 확대, 링크 단절 → 마지막 위치 + 확대 반경, QP infeasible → 감속 | |
| UWB 접근 | 시간 분할(TDMA) 필수 | 동글 비콘으로 슬롯 동기 |
| BLE 연결 간격 | 짧게 유지 (7.5 ms 쪽) | 이벤트 트리거로 전송을 줄여도 간격은 줄이지 않음 |

## 6. 지연 예산 (요약)

| 체인 | 지연 | 근거 수준 |
| --- | --- | --- |
| 내 위치 (UWB → FC) | 약 6 ~ 15 ms | 계산 · 추정 |
| 이웃 상태 (BLE 2홉) | 약 60 ~ 80 ms (간격 7.5 ms) ~ 220 ms 이상 (간격 100 ms) | 실측 RTT에서 계산 |
| 장애물 (ToF → FC) | 약 13 ~ 50 ms | 계산 |
| 속도 추종 τ | 0.2 ~ 1.0 s | 가정. **실측 필요** |

상세는 [지연 분석](../하드웨어/05_지연_분석.md)에 있다.

## 7. 시계 동기

기존 설계는 chrony(NTP)를 전제했으나 N6는 Linux가 없는 MCU라 쓸 수 없다. N6 단조 시계를 기준으로 FC는 MAVLink 시간 동기, 기체 간은 동글 비콘으로 오프셋을 추정하는 안을 제안한다. 미결정이다. 상세는 [전처리 6절](../하드웨어/04_전처리_보정.md#6-시계-동기).
