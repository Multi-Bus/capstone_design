# 5. 발표 시나리오

초안. 10분 기준, 슬라이드 10장. 수치는 [2-하드웨어](2-하드웨어.md), [1-설계](1-설계.md) 기준이다.

| # | 슬라이드 | 핵심 메시지 | 시간 |
| --- | --- | --- | --- |
| 1 | 문제 | 물류센터 실내(GPS 없음)에서 드론 여러 대가 서로 피하며 일해야 한다. 기체가 늘수록 간섭도 늘고, 연산 · 통신 부담도 는다 | 1:00 |
| 2 | 목표 | 6대가 랜덤 목표점으로 무충돌 도달. 연산량 · 통신량 절감 | 0:30 |
| 3 | 접근 | 편대 제어 + CBF-QP 안전 필터. 경량화는 통신 빈도 축소(이벤트 트리거) 우선 | 1:00 |
| 4 | 시스템 구성 | UWB 앵커 → 태그 → N6 → FC, BLE로 이웃 상태, ToF 장애물 (구성도) | 1:00 |
| 5 | 좌표계 결정 | 360° 카메라 폐기 → UWB 앵커 3개로 월드 프레임. 통과 기준 0.10 / 0.15 m. 실패 시 ZED 2i | 1:00 |
| 6 | 실측 1: UWB | LOS 오차 2 cm 안팎. 사람 · 벽 가림이 +29 ~ 36 cm → 이상치 제거 필요 | 1:00 |
| 7 | 실측 2: BLE | 50 Hz × 64 B 손실 0. RTT는 연결 간격이 결정 (26 ms ~ 180 ms). 20 m 1회 수신 부족 | 1:00 |
| 8 | 안전 여유 | D_eff = D_base + 오차 상한. 지연이 길수록 여유가 커져 교착 위험 | 1:00 |
| 9 | 실험 설계와 현황 | E1 ~ E6, 완료 / 남은 일, 가장 큰 미지수 τ | 1:00 |
| 10 | 일정과 위험 | 종강 제출 12/14. UWB 실패 시 전환, 탑재 중량, 시계 동기 | 0:30 |

## 말할 순서의 논리

문제 → 왜 UWB인가(결정 과정) → 실측으로 확인한 것과 못 한 것 → 그래서 남은 일. 결정마다 근거 수치를 붙이고, 가정은 가정이라고 말한다.

## 예상 질문

| 질문 | 답 |
| --- | --- |
| 왜 카메라를 버렸나 | 천장 360° 카메라는 시야각과 정확도 한계. 센서를 늘리면 무게와 전력이 는다 |
| UWB가 정확하지 않으면 | LOS 오차는 작고 가림이 문제. 이상치 제거와 앵커 증설을 검토. 실패 시 ZED 2i 전환 |
| 왜 BLE인가 | 실측에서 요구치(64 B × 50 Hz)를 손실 0으로 처리. Wi-Fi 대비 MCU 부담이 작다는 점은 비교 실험 전이라 단정하지 않음 |
| 안전을 어떻게 보장하나 | CBF-QP가 명령을 최소 보정. 이웃 · 내 위치 오차 상한을 안전거리에 더함 |
| 경량화를 어떻게 증명하나 | E1 ~ E6에서 통신량, 계산 시간, 메모리, 전력을 같은 방식으로 기록 |
| 가장 큰 위험 | 속도 추종 지연 τ (아직 실측 없음). 이 값이 안전 여유를 정함 |
| 6대 실제 비행은 | 부품은 구매 완료. 모터 4개와 프롭 1세트 부족. 비행 시험은 τ 측정부터 |
