# 부품별 입출력과 연산

기체 1대 기준, 현재 부품만 다룬다. 각 부품이 무엇을 받아 무엇을 내보내는지(1절), 그 값이 어디에 쓰이는지(2절), 부품 안에서 어떤 소프트웨어 연산이 도는지(3절), UWB 갱신율(4절), 시간 순서 데이터 경로(5절), 시계(6절) 순서로 정리한다.

근거 표기: (실측) 벤치 측정, (확인) 문서 출처, (계산) 산수, (추정), (가정), [미확인], [제안]. 구현된 소프트웨어는 BLE 링크(XIAO, 동글)와 측정 스크립트뿐이고 나머지는 설계 단계다. 알고리즘 자체는 [편대 제어와 충돌 회피](../소프트웨어/01_편대제어_충돌회피_알고리즘.md), 부품 사이 연결은 [시스템 구조도](../설계/01_시스템_구조도.md).

## 2. 값 → 사용처

| 값 | 만드는 곳 | 쓰는 곳 |
| --- | --- | --- |
| UWB 위치 (x, y) | 앵커 3 + 태그 + N6 | FC EKF(자기 위치), EKF를 거쳐 이웃 방송 |
| 고도 z | MTF-01 거리(경사 보정) 또는 기압 | UWB 수평거리 보정, ODOMETRY z |
| 내 속도 | FC EKF (광류 + IMU) | 이웃 방송, 충돌 회피(이웃 속도와 짝) |
| yaw | FC(컴퍼스) 또는 외부 [미확인] | 월드(방) ↔ NED 회전, 카메라 방위 변환 |
| 이웃 예측 위치 · 속도 | 무선 패킷 + 외삽 | 충돌 회피 제약, 편대 제어 |
| 이웃과의 거리 (UWB) | 태그 ↔ 태그 | 통신 위치와 교차검사, 통신 단절 시 충돌 회피 보조 (보류) |
| ToF 거리 | VL53L1X | CBF 장애물 제약 + FC 근접 회피(이중 안전층) |
| 카메라 방위 | STEVAL | 보이는 이웃의 위치 보정 (선택, 후순위) |

## 3. 부품별 소프트웨어 연산

### 3.1 UWB 앵커와 태그 (DWM3000)

| 연산 | 입력 | 출력 |
| --- | --- | --- |
| 거리 측정 (양방향 측거) | 앵커와 주고받은 프레임의 송수신 시각 | 앵커별 직선거리 |
| 수신 진단 | 수신 신호 | 첫 경로 전력, 전체 수신 전력 (이상치 판단용) |

- 거리는 시간 차에서 나온 계산값이다. 거리값을 실어 보내지 않는다.
- N6가 SPI로 읽는다.
- 앵커 3개를 번갈아 부르고, 6대가 겹치지 않게 시간 분할이 필요하다 [설계 필요].

### 3.2 ToF와 MTF-01

| 부품 | 연산 | 입력 | 출력 |
| --- | --- | --- | --- |
| ToF ×5 | 방향별 거리 측정 | 센서 방향의 반사 | 거리, 측정 상태 |
| MTF-01 | 고도 · 광류 측정 | 바닥면 | 높이, 수평 이동 속도 |

MTF-01 값은 FC가 직접 쓰고, N6는 높이만 필요하다(UWB 직선거리에서 높이 차를 빼는 데 쓴다).

### 3.3 FC (H743, ArduPilot)

| 연산 | 입력 | 출력 |
| --- | --- | --- |
| 상태 추정 (EKF) | N6의 UWB 위치, 광류 속도, IMU | 융합된 위치 · 속도 · 자세 (N6로 회신) |
| 속도 · 자세 · 각속도 제어 | N6의 속도 명령 | 모터 출력 |
| (보조) ToF 근접 회피 | ToF 거리 | 정지 · 감속 |

- 속도 명령이 끊기면 3초 뒤 정지한다(ArduPilot 확인).
- N6와 UART 460800 baud 이상이 필요하다. 115200은 부족하다(약 139 kbaud 필요).
- 펌웨어 확정 여부는 확인이 필요하다.

### 3.4 N6 (NUCLEO-N657X0-Q)

Linux 없는 MCU. RTOS 또는 베어메탈. 아래 일곱 가지 일을 한다.

#### 3.4.1 내 위치 계산

| 단계 | 입력 | 출력 |
| --- | --- | --- |
| 수평거리 환산 | 앵커별 직선거리, MTF-01 높이, 앵커 높이 | 앵커별 수평거리 |
| 이상치 제거 | 수평거리, 첫 경로 전력, 직전 예측 위치 | 쓸 수 있는 수평거리 |
| 3점 위치 계산 (가우스-뉴턴 최소제곱) | 수평거리 3개, 앵커 좌표, 직전 위치 | 평면 위치 (x, y) |
| 좌표 변환 + 포장 | 위치, 높이, 월드 → NED 변환 | ODOMETRY (공분산 포함) → FC |

- 이동평균은 쓰지 않는다. 3점 평균은 20 Hz에서 50 ms 지연이라 평활은 FC EKF에 맡긴다.
- 앵커 4개 잔차 검사는 보류(팀 합의 필요).

#### 3.4.2 이웃 정보 처리

| 단계 | 입력 | 출력 |
| --- | --- | --- |
| 순번 검사 | 이웃 패킷 (id, 순번, 보낸 시각, 위치, 속도) | 새 패킷만 통과 (손실 · 순서 뒤바뀜 처리) |
| 시계 보정 | 보낸 시각, 시간 맞춤 신호 | 내 시계 기준 보낸 시각 |
| 위치 외삽 | 이웃 위치, 속도, 보낸 시각, 지금 시각 | 이웃 예측 위치 |
| 정보 나이 · 낡음 판정 | 보낸 시각, 지금 시각 | 정보 나이, 낡음 여부 (히스테리시스) |

- 이웃 예측 위치 = 보낸 위치 + 이웃 속도 × (지금 시각 − 보낸 시각).
- 시계 보정은 왕복 시간 절반 근사를 쓰는 안이다. 동기 방식은 미결정이다 [설계 필요].
- 이웃 패킷 크기와 주기: 64 B × 50 Hz가 BLE 실측 요구치. 구설계 31 B × 20 Hz와 팀 합의가 필요하다.

#### 3.4.3 장애물 점 생성

| 단계 | 입력 | 출력 |
| --- | --- | --- |
| 상태 필터 · 2회 연속 확인 | ToF 거리, 측정 상태 | 믿을 만한 거리 (오경보 감소) |
| 몸체 → 월드 변환 | 거리, 센서 방향, FC 자세, 내 위치 | 월드 좌표 장애물 점 |
| 이웃 중복 제거 | 장애물 점, 이웃 예측 위치 | 이웃이 아닌 점만 (이웃을 정지 장애물로 두 번 세지 않음) |

#### 3.4.4 편대 제어와 충돌 회피

| 단계 | 입력 | 출력 |
| --- | --- | --- |
| 편대 제어 | 내 위치, 이웃 예측 위치, 역할 번호(대형 위치), 편대 이동 속도 | 원하는 속도 |
| 충돌 회피 (CBF-QP) | 원하는 속도, 이웃 예측 위치 · 속도 · 정보 나이, 장애물 점 | 안전 속도 |
| 속도 명령 | 안전 속도 (NED) | 속도 명령 (MAVLink) → FC, 20 ~ 50 Hz |

- 편대 제어와 충돌 회피는 `원하는 속도 → 안전 속도` 함수 하나로 분리한다. 회피 알고리즘을 바꿔 끼울 때 이 경계를 지킨다.
- 알고리즘 내용은 [02](../소프트웨어/01_편대제어_충돌회피_알고리즘.md).

#### 3.4.5 송신 판단 (이벤트 트리거)

| 입력 | 출력 |
| --- | --- |
| 내 현재 상태, 마지막으로 보낸 값과 시각 | 보낼지 말지 (보내면 이웃 패킷) |

- 마지막으로 보낸 값으로 수신 쪽 예측을 자기도 계산한다. 실제 위치와 예측 위치의 차이가 기준을 넘거나, 마지막 전송 후 시간이 한계를 넘으면 보낸다.
- 시간 한계는 생존 신호다. 메시지 없음이 변화 없음은 아니므로, 링크 단절과 예측 정확을 구분하려고 둔다.

#### 3.4.6 이상 상황 처리

| 상황 | 대응 |
| --- | --- |
| 이웃 정보 낡음 | 안전거리 확대 |
| 링크 단절 | 마지막 위치 + 확대 반경 |
| 해 없음 (사방이 막힘) | 감속 · 정지 |
| 속도 명령 끊김 | FC가 3초 뒤 정지 |

#### 3.4.7 기록

| 입력 | 출력 |
| --- | --- |
| 모든 모듈의 값, 송수신 타임스탬프 | SD 로그, 동글 텔레메트리 |

- RAM 링 버퍼에 쌓고 DMA로 SD에 쓴다. SD 쓰기 지연이 제어 루프에 영향을 주지 않게 한다.

### 3.5 XIAO nRF52840

| 연산 | 입력 | 출력 |
| --- | --- | --- |
| 이웃 패킷 방송 | N6가 UART로 준 패킷 | BLE 방송 / 연결 전송 |
| 이웃 패킷 수신 | 이웃의 BLE 패킷 | N6로 UART 전달 |

- BLE 연결 간격은 짧게(7.5 ms 쪽) 유지한다. 이벤트 트리거로 전송을 줄여도 간격은 줄이지 않는다.
- 이웃 교환을 UWB 프레임에 실어 보내는 방식이 채택되면 이 부분이 바뀐다(UWB 페이로드는 시험 전).

### 3.6 PC + 동글

| 연산 | 입력 | 출력 |
| --- | --- | --- |
| 로그 수집 | 드론의 텔레메트리 | 실험 기록 |
| 목표 배포 | 사용자 목표 | 드론별 목표 |
| 시간 맞춤 신호 | (없음) | 주기적 비콘 (시간 분할 · 시계 보정용) [제안] |
| 중계 (BLE 2홉일 때만) | 한 드론의 패킷 | 다른 드론 |

## 4. UWB 갱신율 설계

한 바퀴 시간 = 기체 수 × (앵커 3 + 이웃 측거 수) × 교환 1회 시간 (추정).

| 조건 | 한 바퀴 | 기체당 갱신율 |
| --- | --- | --- |
| DS-TWR 1회 1 ~ 3 ms 가정, 6대, 이웃 측거 2 | 30 ~ 90 ms | 약 11 ~ 33 Hz |
| 같은 가정, 이웃 측거 5 (전원) | 48 ~ 144 ms | 약 7 ~ 21 Hz |

참고: Crazyflie 13대 피어 UWB는 16 Hz(확인), Bitcraze TWR은 태그 4개에서 태그당 10 Hz 안팎(확인). ArduPilot 외부 위치는 최소 4 Hz, 권장 30 Hz급(확인). **시간 분할(TDMA) 없이 각자 측정하면 충돌한다.** 슬롯 동기는 동글 비콘으로 맞추는 방안 [제안].

## 5. 시간 순서로 본 데이터 경로

| 단계 | 구간 | 메시지 | 주기 |
| --- | --- | --- | --- |
| 1 | 앵커 ↔ 태그 | UWB TWR 프레임 | 11 ~ 33 Hz (추정) |
| 2 | 태그 → N6 | SPI 타임스탬프 | 이벤트 |
| 3 | N6 → FC | ODOMETRY 약 245 B | 20 ~ 30 Hz |
| 4 | FC → N6 | 융합 상태 | FC 설정 |
| 5 | N6 → XIAO → BLE | 내 상태 64 B | 50 Hz 기준선, 이벤트 트리거로 감소 |
| 6 | BLE → XIAO → N6 | 이웃 상태 64 B | 이웃 수 × 방송 주기 |
| 7 | ToF → N6 | 5개 거리 | 연속 모드, 한 바퀴 약 3 ms 읽기 (계산) |
| 8 | N6 → FC | 속도 명령 약 65 B | 20 ~ 50 Hz |
| 9 | N6 → FC | DISTANCE_SENSOR 약 30 B × 5 | 10 ~ 50 Hz |

## 6. 시계

기존 설계는 chrony(NTP)를 전제했으나 N6는 Linux가 없어 쓸 수 없다. N6 단조 시계를 기준으로 FC는 MAVLink 시간 동기, 기체 간은 동글 비콘으로 오프셋을 추정하는 안을 제안한다. 미결정이다. 상세는 [전처리 6절](04_전처리_보정.md#6-시계-동기).
