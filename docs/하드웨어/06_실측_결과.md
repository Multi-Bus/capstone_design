## Task 4: XIAO nRF52840 ↔ 동글 (2026-11-09)

| 측정 | 결과 |
| --- | --- |
| 처리량 | 20 ~ 240 B, 연결 간격 7.5 ~ 100 ms 전 조건 3.2 kB/s 이상. 최고 약 109.5 kB/s (240 B, 15 ms) |
| 요구치 50 Hz × 64 B | 간격 7.5 / 30 / 100 ms 모두 손실 0 (9회, 27,013 패킷) |
| RTT (1,000회) | 7.5 ms 간격 평균 26 ms(최대 31.4 ms), 30 ms 간격 55 ms, 100 ms 간격 180 ms. 응답률 100% |
| 거리별 (50 Hz × 64 B, 각 60 s, 실내 복도) | 1 / 5 / 10 m 손실 없음 (RSSI -58 / -72 / -76 dBm). 20 m 4회 중 3회 정상, 1회 수신 28.9% 부족 (원인 미확인) |

해석: 왕복 지연은 연결 간격이 정한다. 이벤트 트리거로 전송 횟수를 줄여도 연결 간격은 짧게 유지한다.

아직 안 한 것: BLE 재연결 시간, 모터 구동 중 성능, UWB와 BLE 동시 구동 간섭, 엔드투엔드(N6 → XIAO → 동글 → PC), 드론 ↔ 드론 2홉.

## 실측이 말해 주는 것

| 질문 | 답 | 근거 |
| --- | --- | --- |
| UWB 거리는 충분히 정확한가 | LOS에서는 그렇다(2 cm 안팎). 가림이 문제다 | Task 1 |
| UWB 위치 통과 기준(RMSE 0.15 m)은 맞는가 | 모른다. 3점 위치 계산과 EVB 측거가 아직 없다 | Task 2 대기 |
| BLE가 요구 통신량을 감당하는가 | 한 홉은 그렇다(손실 0) | Task 4 |
| BLE 지연이 안전 여유에 영향을 주는가 | 준다. 간격 7.5 ms와 100 ms는 D_eff 0.3 m 차이 | Task 4 + 계산 |
| N6가 제어 루프를 돌릴 만큼 빠른가 | 기초 연산은 그렇다. QP는 모른다 | Task 3 |
| ToF 5개가 한 번에 읽히는가 | 모른다 | Task 5 대기 |
| 기체가 속도 명령을 얼마나 빨리 따르는가 | 모른다 | 기체 시험 대기 |

## 막힌 곳과 해결 (대표 사례)

- 동글에 central 펌웨어를 올리면 USB 미인식 → `CONFIG_BT_SETTINGS=n`.
- 최대 속도 송신에서 손실 22 ~ 75% → MTU 247, ACL 버퍼 251, 힙 16384 B로 확대.
- 연결 콜백에서 PHY, MTU, 연결 간격을 동시에 요청하면 알림 구독 실패 → 측정 전에 명령으로만 요청.
