# SD 로더 설계 (1단계)

NUCLEO-N657 브리지 펌웨어를 바꿀 때마다 점퍼를 바꾸고 ST-LINK를 연결하던 것을, SD 카드 파일 교체로 바꾼다.
외부 플래시에는 작은 로더를 한 번만 쓰고, 로더가 부팅할 때 SD 카드의 펌웨어를 RAM에 올려 실행한다.

## 1. 동작

```
전원 ON (비행 점퍼: BOOT0 1-2, BOOT1 1-2, CN9 3-4)
  → 부트롬이 외부 플래시의 로더(FSBL)를 0x34180400 에 올려 실행
  → 로더: SD 카드에서 N6APP.BIN 을 찾고 검사
      통과   → 그 펌웨어를 AXISRAM1(0x34000400) 에 복사하고 실행
      실패   → 로더 안에 넣어 둔 기본 펌웨어를 같은 자리에 복사하고 실행
  (단, 바로 앞 부팅이 SD 펌웨어였고 전원이 꺼지지 않은 리셋이면 SD 를 건너뛰고 기본 펌웨어. 5-1장)
```

- 점퍼는 비행용 그대로 둔다. 점퍼를 바꾸는 것은 로더를 처음 쓸 때와 로더 자체를 고칠 때뿐이다.
- 기본 펌웨어는 지금 기체에 올라간 것(`tagf-v2-lfs`, 기체별 id)과 같은 소스로 빌드한다. SD 카드가 없거나 파일이 나빠도 지금과 똑같이 난다.
- 펌웨어를 바꾸는 방법: 배터리를 빼고, SD 카드를 PC에서 바꾸고, 다시 꽂고 배터리를 연결한다.

## 2. 메모리 배치

| 영역 | 주소 | 크기 | 쓰는 것 |
| --- | --- | --- | --- |
| 외부 플래시 | `0x70000000` | 서명 헤더 + 로더 + 기본 펌웨어 (약 200 KB 예상) | 부트롬이 읽음 |
| AXISRAM2 FSBL 자리 | `0x34180400` | 255 KB (`STM32N657X0HXQ_AXISRAM2_fsbl.ld` ROM) | 로더 코드 + 기본 펌웨어 묶음 |
| AXISRAM2 RAM | `0x341C0000` | 256 KB | 로더의 변수와 스택. 펌웨어로 넘어간 뒤에는 펌웨어의 변수와 스택(지금과 같은 자리) |
| AXISRAM1 | `0x34000400` | 최대 512 KB로 제한 | 펌웨어 코드 (SD 또는 기본) |

- 지금 펌웨어는 코드 약 111 KB, 변수 약 88 KB(`.data` + `.bss` + 힙·스택)이다.
- 펌웨어는 코드 시작 주소만 `0x34180400`에서 `0x34000400`으로 바꿔 다시 링크한다. RAM 자리는 그대로 둔다.
  펌웨어의 벡터 표 주소는 링커 기호(`INTVECT_START`)로 정해지므로 소스는 바꾸지 않는다.
- 로더는 복사 전에 `RCC_MEMENR.AXISRAM1EN`을 켠다. 켜야 하는지(리셋 값)는 RAM 시험에서 확인한다.

## 3. SD 파일 `N6APP.BIN`

FAT32 카드 맨 위 폴더에 둔다. 기록 파일 `UWBLOG.BIN`과 같은 카드를 쓴다. 로더는 지금 펌웨어의 `sdfat.c`로 파일을 찾으므로
**파일이 한 덩어리로 이어져 있어야 한다**(조각나면 기본 펌웨어로 실행하고 `reason=fragmented`를 남긴다).
`UWBLOG.BIN`을 만든 카드에 이어서 쓰면 보통 한 덩어리가 된다.

앞 32바이트 헤더 + 펌웨어 바이너리(`objcopy -O binary`):

| 위치 | 크기 | 내용 |
| --- | --- | --- |
| 0 | 4 | 표시 `N6AP` |
| 4 | 2 | 헤더 판 `1` |
| 6 | 1 | 태그 id (0~5, 기체 번호 - 1) |
| 7 | 1 | 예약 `0` |
| 8 | 4 | 올릴 주소 `0x34000400` |
| 12 | 4 | 펌웨어 길이 (바이트) |
| 16 | 4 | 펌웨어 CRC-32 (IEEE, zlib 과 같음) |
| 20 | 12 | 펌웨어 이름 (예 `tagf-v2-lfs`, 남는 칸 0) |

## 4. 로더가 검사하는 것

하나라도 틀리면 SD 파일을 쓰지 않고 기본 펌웨어로 실행한다.

1. SD 카드가 켜지고 FAT32로 읽힌다 (배터리 없이 USB 전원만이면 여기서 실패)
2. `N6APP.BIN`이 있고 한 덩어리다
3. 표시 `N6AP`, 헤더 판 `1`
4. 태그 id가 로더의 id와 같다 (카드를 다른 기체에 꽂은 경우를 막음)
5. 올릴 주소가 `0x34000400`, 길이가 1 ~ 512 KB, 파일 크기가 헤더 + 길이 이상
6. 복사한 내용의 CRC-32가 헤더와 같다
7. 벡터 표: 첫 스택 값이 RAM(`0x341C0000`~`0x34200000`) 안, 시작 주소가 펌웨어 범위 안

## 5. 넘겨주기 (로더 → 펌웨어)

- 로더는 클록을 바꾸지 않는다. 부트롬이 둔 상태에서 SD만 읽는다. 펌웨어가 지금처럼 클록을 처음부터 설정할 수 있게 하기 위해서다.
- 넘기기 전에 SD(`SDMMC2`)를 리셋하고, 인터럽트를 끄고, SysTick을 끄고, 데이터 캐시를 비우고 명령 캐시를 무효로 한다.
- 펌웨어의 벡터 표에서 스택 값과 시작 주소를 읽어 MSP를 바꾸고 뛴다.

### 5-1. SD 펌웨어가 멈추거나 오류가 났을 때

- 로더는 SD 펌웨어로 넘기기 직전에 백업 레지스터 `TAMP->BKP0R`에 표시(`N6SD`)를 남긴다. 이 레지스터는 리셋으로 지워지지 않는다.
- 로더는 시작할 때 표시를 읽고 바로 지운다. 그리고:
  - 전원을 새로 켠 부팅(`RCC->RSR`의 POR 또는 BOR 표시)이면 표시를 무시하고 SD를 시도한다.
  - 전원이 꺼지지 않은 리셋인데 표시가 있으면 SD를 건너뛰고 기본 펌웨어로 켠다(`reason=after_reset`). 한 번만 그렇게 하고, 그다음 리셋은 다시 SD를 시도한다.
- 펌웨어(SD, 기본 모두)는 오류(HardFault)가 나면 멈춰 있지 않고 바로 리셋한다. 그래서 SD 펌웨어가 오류로 죽으면 자동으로 기본 펌웨어로 다시 켜진다.
- SD 펌웨어가 오류 없이 멈춘 경우(무한 대기 등)는 NUCLEO의 RESET 버튼(B2)을 누르면 기본 펌웨어로 켜진다. 배터리를 뺐다 꽂으면 다시 SD 펌웨어다.
- 와치독은 쓰지 않는다. 한 번 켜면 끌 수 없고, 정상 펌웨어가 잠깐 늦을 때 비행 중 리셋될 수 있어서다.
- 비행 중 브리지가 멈추면 지금과 같이 FC가 노트북 하트비트를 3초 못 받고 스스로 LAND한다(`FS_GCS_ENABLE 5`, `FS_GCS_TIMEOUT 3`).

### 5-2. 지연시간

- SD를 읽는 것은 부팅 때 한 번뿐이다. 펌웨어는 지금처럼 칩 안 SRAM에서 돌고, AXISRAM1과 AXISRAM2는 같은 종류의 메모리라 실행 속도가 같다. 비행 중 BLE 중계, FC 연결, UWB 프레임 주기는 달라지지 않는다.
- 부팅만 늦어진다. 카드 전원을 껐다 켜는 데 0.5초(`sdlog.c`와 같은 순서), 113 KB를 읽는 데 약 0.1~0.3초를 예상한다. 로더 줄에 걸린 시간(`ms=`)을 남긴다.

### 5-3. 운영 규칙

- 새 `N6APP.BIN`은 바닥에서 `n6_fly.py --no-arm`으로 양방향 통신을 확인한 뒤 호버한다.
- 비행 전에 로더 줄(`src=sd` 또는 `src=builtin`)로 어느 펌웨어로 켜졌는지 확인한다.

## 6. 기록

로더는 ST-LINK 가상 COM(921600)에 한 줄을 남긴다. 그다음 줄부터는 펌웨어의 줄(`TF_READY` 등)이다.

```
LDR,ver=1,id=3,src=sd,fw=tagf-v2-lfs,len=113376,crc=0x1234abcd,ms=640
LDR,ver=1,id=3,src=builtin,reason=no_file,len=113376,ms=600
```

`reason`: `no_card`, `no_fat`, `no_file`, `fragmented`, `read_error`, `bad_magic`, `bad_version`, `wrong_id`, `bad_length`, `bad_crc`, `bad_vectors`, `after_reset`.

## 7. 만들 것

| 경로 | 내용 |
| --- | --- |
| `firmware/uwb/n6_sd_loader/loader/loader.c` | 로더 본체 (SD 열기, 검사, 복사, 넘겨주기) |
| `firmware/uwb/n6_sd_loader/loader/app_header.c/.h` | 헤더 검사 함수. 보드와 PC 시험이 같이 씀 |
| `firmware/uwb/n6_sd_loader/loader/prepare_loader.py` | 핸드오프 FSBL 프로젝트 복사본에 로더를 설치하고, 기본 펌웨어를 넣음 |
| `firmware/uwb/n6_flight_tag/tag/prepare_tag.py` | `--app-link` 추가: 코드 시작 주소를 `0x34000400`으로 바꾸고, HardFault 때 리셋하게 함 |
| `firmware/uwb/n6_sd_loader/tools/sd_app.py` | 펌웨어 `.bin`에 헤더를 붙여 `N6APP.BIN`을 만들고 카드에 써서 다시 읽어 대조 |
| `firmware/uwb/n6_sd_loader/tools/test_sd_app.py` | 헤더 만들기와 C 검사 함수(공유 라이브러리) 시험 |

SD 읽기는 `n6_flight_tag/tag/`의 `sdlog.c`(`sdlog_init`, `sdlog_read_block`)와 `sdfat.c`(`sdfat_locate`)를 그대로 쓴다.

## 8. 시험 순서

| 단계 | 확인 | 장소 |
| --- | --- | --- |
| 1 | 헤더 만들기와 검사 함수: 정상, 위 `reason` 각각 | PC (`test_sd_app.py`) |
| 2 | `--app-link`로 빌드한 펌웨어를 `load_tag.py`로 AXISRAM1에 직접 올려 `TF_READY`, FC 수신, SD 기록 | 보드 RAM |
| 3 | 로더 RAM 실행, 카드 없음(또는 USB 전원만) → `src=builtin` 그리고 펌웨어 정상 | 보드 RAM |
| 4 | 정상 `N6APP.BIN` → `src=sd` 그리고 펌웨어 정상 | 보드 RAM |
| 5 | CRC 틀린 파일, 다른 id 파일 → `src=builtin` | 보드 RAM |
| 5-1 | SD로 켠 뒤 RESET 버튼 → `reason=after_reset`, 한 번 더 RESET → `src=sd`, 배터리 뺐다 꽂음 → `src=sd` | 보드 |
| 6 | 백업 → 로더 플래시 쓰기·대조 → 비행 점퍼로 부팅 → `--no-arm` → 1.3 m 호버 | 한 기체 |
| 7 | 나머지 기체에 같은 순서 | 기체별 |

2~5는 개발 점퍼(BOOT1 2-3, CN9 1-2)와 배터리 연결 상태에서 한다(SD 카드 전원).

## 9. 하지 않는 것

- 와치독으로 멈춤을 자동으로 잡기 (5-1장 이유).
- 무선(BLE) 업데이트, 로더 자체를 SD로 업데이트하기.
- 칩의 SD 직접 부팅(OTP 퓨즈를 써야 해서 되돌릴 수 없음).
- 펌웨어 서명 검사. CRC는 깨진 파일을 막을 뿐, 고의로 만든 파일은 막지 않는다.

## 10. 위험과 확인할 것

| 위험 | 확인 방법 |
| --- | --- |
| AXISRAM1을 켜야 하거나 부트롬 뒤에 접근이 막혀 있음 | 시험 2 (펌웨어를 AXISRAM1에 직접 올림) |
| 펌웨어가 클록을 다시 설정할 때, 로더가 남긴 상태 때문에 실패 | 로더는 클록을 건드리지 않음. 시험 3·4에서 `TF_READY`와 UART 속도 확인 |
| 부트롬이 둔 클록에서 SD 읽기가 느림 (113 KB) | 시험 4에서 로더 시작부터 `TF_READY`까지 시간 기록. 1초 안 목표 |
| 서명 이미지 크기 한도 (FSBL 255 KB) | 로더 + 기본 펌웨어 크기를 빌드 때 검사 |
| 기체마다 id가 다른 로더 6개를 관리 | 지금 `id0~id5` 빌드와 같은 방식으로 6개 빌드, `SHA256.txt`에 기록 |
