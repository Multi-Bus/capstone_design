# 비행용 태그 펌웨어: BLE 중계 + UWB 프레임 + SD 기록 + 대본 (2026-11-24)

드론의 NUCLEO-N657X0-Q(+ DWM3000EVB)에 올리는 펌웨어입니다. 지금 드론에 들어 있는 BLE 중계 펌웨어(`n6_bridge`)를 대신합니다.

**이 펌웨어는 실제 보드에서 돌려 보지 않았습니다.** 컴파일(오류·경고 0)과 PC 시험까지 했습니다.
처음에는 반드시 프롭을 떼고 6장의 순서대로 확인하세요.

## 1. 하는 일

```
노트북 n6_fly.py --BLE--> XIAO --USART2--> [이 펌웨어] --UART7--> 비행 제어기
                                              │
                                              ├ UWB: 앵커 1 의 프레임에 맞춰 위치 측정, heartbeat, 추가 슬롯
                                              ├ SD: 프레임 줄, 패킷 줄, 거리 줄, 비행 제어기 값
                                              └ 대본: 프레임 번호에 따라 비행 제어기에 속도 명령
```

| 부분 | 내용 |
|---|---|
| BLE 중계 | 노트북과 비행 제어기 사이의 MAVLink 를 메시지 단위로 그대로 넘깁니다. `n6_fly.py` 가 보내는 명령은 그대로 통과합니다 |
| 비행 제어기 값 | 보드가 위치·속도(50 Hz)와 자세(10 Hz)를 요청해 읽고 기록합니다. 노트북 쪽으로는 5 Hz, 2 Hz 로 줄여 넘깁니다 |
| 대본 | 앵커 1 의 질문 패킷에 실린 대본 번호, 시작 프레임, 속도대로 속도 명령을 보냅니다 (10 Hz, 값이 바뀌면 바로) |
| 속도 명령 | `SET_POSITION_TARGET_LOCAL_NED`, 기체 기준(앞 +x, 오른쪽 +y), 높이 유지, 기수 방향 유지(회전 속도 0) |
| 제어 계산 | 프레임마다 한 번, 무선이 끝난 직후. 시작·끝 시각을 프레임 줄에 남깁니다 |

## 2. 대본과 앵커 1

대본은 앵커 1 을 빌드할 때 정합니다. **앵커 1 을 켠 때부터 프레임 번호를 세고, 시작 프레임(기본 1500 = 30초 뒤)에 대본이 시작됩니다.**
여섯 기체가 같은 프레임 번호에 같은 줄을 실행합니다. 앵커에는 명령을 보내지 않습니다(보조 배터리로 켜 두기만 함).

| 대본 | 내용 | 걸리는 시간 (0.3 m/s) | 구역 한도 |
|---|---|---|---|
| 1 | 앞 2 m → 5 s → 원점 → 5 s → 오른쪽 2 m → 5 s → 원점 → 5 s | 46.7 s | 시작한 자리에서 3.5 m |
| 2 | 앞 4 m → 5 s → 원점 → 5 s | 36.7 s | 5.5 m |
| 3 | 앞 3 m → 10 s → 원점 → 5 s | 35.0 s | 4.5 m |
| 4 | 제자리 60 s (속도 0 명령을 계속 보냄) | 60 s | 1.5 m |

미리 빌드해 둔 앵커 1 (앵커 묶음의 `build/f/`). 올릴 때는 `py flash.py --packets f --id 1 --variant <이름> --serial <J-Link>`.

| 이름 | 설정 | 쓰는 단계 (설계서 7.2, 7.3) |
|---|---|---|
| (없음) | 추가 슬롯 1, 대본 없음 | 0단계, 1단계, 4단계 (30대에 해당하는 설정) |
| `k3` | 추가 슬롯 3, 대본 없음 | 0, 1단계 (16대에 해당) |
| `k0`, `k5` | 추가 슬롯 0, 5 | 시간이 되면 |
| `x3` | 추가 슬롯 3을 교환으로 | 교환 시간 재기 |
| `d1` | 일정을 드론 0번이 보냄 | 5단계 |
| `s4` | 대본 4 (제자리) | 속도 0 명령으로 제자리를 볼 때 |
| `s1v30` | 대본 1, 0.3 m/s, 모두 | 2단계 |
| `s2v30m0`, `s2v50m0`, `s2v70m0`, `s2v100m0` | 대본 2, 드론 0번만 움직임 | 3단계 (최대 속도) |
| `s2v50`, `s2v100` | 대본 2, 모두 | 한 대로 하는 7.2 자 |
| `s3v50`, `s3v100` | 대본 3, 모두 | 한 대로 하는 7.2 차 |

다른 조합은 `py build.py --packets f --id 1 --variant <이름> --script N --script-speed <cm/s> --script-limit <cm/s> --script-mover <번호> --script-start <프레임>` 으로 만듭니다(arm-none-eabi-gcc 필요).

같은 대본을 시뮬레이터에 넣을 표: `py tools\script_table.py --script 1 --speed 30 --start 1500 --out script1.csv`

## 3. 안전

| 상황 | 보드가 하는 일 |
|---|---|
| 시작 프레임에 시동 + GUIDED + 위치 값(0.5초 안) + SD 기록이 되는 중이 아님 | 그 대본에 끼지 않음(아무것도 안 보냄). 앵커 1 을 다시 켜기 전에는 끼지 않음 |
| 도는 중에 비행 모드가 GUIDED 가 아니게 됨 (**조종기 스위치**, 노트북의 스페이스 = LAND) | 바로 그만둠. 속도 명령도 다른 명령도 보내지 않음 |
| 시작한 자리에서 구역 한도보다 멀어짐 | LAND 모드 명령 3번 (노트북의 킬과 같은 명령) |
| SD 기록이 2초 넘게 안 됨 | LAND 모드 명령 3번 |
| 앵커 1 의 질문이 0.5초 끊김 | 속도 0 을 5번 보내고 그만둠 |
| 비행 제어기의 위치 값이 0.5초 끊김, HEARTBEAT 가 1.5초 끊김 | 속도 0 을 5번 보내고 그만둠 |
| 시동이 꺼짐 | 그만둠 |
| 대본이 끝남 | 속도 0 을 5번 보내고 그침. 기체는 GUIDED 로 제자리에 남음 |
| 대본 속도가 한도보다 큼 | 앵커 1 이 보낸 한도와 펌웨어의 절대 한도(1.0 m/s) 가운데 작은 값으로 자름 |

- 한 번 그만두면 이어서 하지 않습니다. 다시 하려면 앵커 1 의 전원을 껐다 켭니다.
- **조종기로 여섯 대를 한 번에 멈추려면 여섯 대의 비행 제어기가 그 스위치로 모드가 바뀌어야 합니다.** 보드는 각자 자기 비행 제어기의 모드만 봅니다.
- UWB 칩이 안 잡혀도(`TF_INIT_FAILED`) BLE 중계는 계속 돕니다.

**비행 제어기에서 사람이 맞춰 둘 것** (QGC 의 Parameters. 이 펌웨어는 파라미터를 쓰지 않습니다)

| 파라미터 | 값 | 이유 |
|---|---|---|
| `GUID_TIMEOUT` | 0.5 | 보드의 속도 명령이 0.5초 끊기면 비행 제어기가 스스로 멈추게 (설계서 8절). 기본값은 3초 |
| `MAV_GCS_SYSID` | 250 (지금 그대로) | 지상국 페일세이프는 노트북의 HEARTBEAT 만 봅니다. 보드는 251번으로 보냅니다 |

`GUID_TIMEOUT` 이라는 이름과 범위는 ArduCopter 4.7 에서 직접 확인하지 못했습니다. QGC 에서 이름을 확인하고 넣으세요.

## 4. 올리기 (외부 플래시)

파일: `tag/build/flight/n6_flight_tagf_v2_id<번호>-trusted.bin` (번호 0~5, 드론마다 다른 번호). 서명 머리는 이미 붙였습니다.
SHA-256 은 `tag/build/flight/SHA256.txt`.

1. 전원을 끈 상태에서 **BOOT1 = 2-3, CN9 = 1-2**, PC 를 **CN10** 에 연결합니다 (`QUICKSTART_KO.md` 1장과 같음).
2. 씁니다.
   ```powershell
   $CUBEPROG = Split-Path (Get-ChildItem C:\ST, "C:\Program Files\STMicroelectronics" -Recurse -Filter STM32_Programmer_CLI.exe -ErrorAction SilentlyContinue | Select-Object -First 1).FullName
   & "$CUBEPROG\STM32_Programmer_CLI.exe" -c port=SWD mode=HOTPLUG -el "$CUBEPROG\ExternalLoader\MX25UM51245G_STM32N6570-NUCLEO.stldr" -hardRst -w tag\build\flight\n6_flight_tagf_v2_id0-trusted.bin 0x70000000
   ```
3. 전원을 끄고 **BOOT0 = 1-2, BOOT1 = 1-2, CN9 = 3-4** 로 되돌립니다.

- 되돌리기: 같은 명령으로 `n6_bridge_FSBL-trusted.bin`(중계만 하는 원래 펌웨어)을 씁니다.
- 플래시에 쓰기 전에 RAM 으로 먼저 돌려 볼 수 있습니다: `py tools\load_tag.py tag\build\flight\n6_flight_tagf_v2_id0.elf`. USB 로 연결된 동안 921600 bit/s 로 기록 줄이 나옵니다.
- 직접 빌드: `py tag\prepare_tag.py --fsbl-copy <사본>\FSBL --packets f --opt O2 --tag-id N --sd --flight --st-package <STM32Cube_FW_N6>` 뒤 CubeIDE 로 Debug 구성 빌드, `objcopy -O binary`, `STM32_SigningTool_CLI -bin ... -nk -of 0x80000000 -t fsbl -o ...-trusted.bin -hv 2.3 -align`.

SD 카드는 `README_FRAME_KO.md` 5장대로 준비합니다(FAT32 포맷 뒤 `py tools\sd_prepare.py --drive E:\`). **카드에 기록이 안 되면 대본은 시작하지 않습니다.**

## 5. 기록 줄 (비행용에서 더 나오는 것)

```
C,<프레임>,<x mm>,<y mm>,<z mm>,<vx mm/s>,<vy>,<vz>,<roll 0.01도>,<pitch>,<yaw>,<위치 나이 ms>,<자세 나이 ms>,<비행 모드>,<시동>,<대본 상태>,<대본 줄>,<명령 vx mm/s>,<명령 vy mm/s>,<명령 보냄>
E,<프레임>,<이름>,<a>,<b>
U,<프레임>,<FC 수신 바이트>,<FC 송신>,<BLE 수신>,<BLE 송신>,<FC 수신 넘침>,<BLE 송신 못 넣음>,<FC 수신 오류>,<BLE 수신 오류>
```

- `C`: 비행 제어기의 새 위치 값이 왔거나 속도 명령을 보낸 프레임마다 한 줄. 위치·속도는 `LOCAL_POSITION_NED`(북, 동, 아래). 명령은 기체 기준.
  - 대본 상태: 0 대기, 1 준비됨(시작 2초 전부터), 2 실행, 3 끝남, 4 그만둠, 5 빠짐
  - "명령이 반영되는 지연"은 이 줄의 명령 칸과 속도 칸으로 계산합니다(`tools\frame_measure.py`).
- `E` 의 이름: `start`, `done`, `skip_notready`(b = 1 GUIDED 아님 + 2 위치 없음 + 4 기록 안 됨), `abort_mode`(a = 모드), `abort_disarm`, `abort_zone`(a, b = 벗어난 mm), `abort_log`, `abort_link`, `abort_stale`, `abort_ctl`, `land_sent`, `fc_seen`, `fc_lost`, `flight_uart`(a = 1 이면 UART 준비됨)
- `U`: 10초마다. 넘침과 오류가 늘면 중계가 바이트를 잃고 있는 것입니다.

## 6. 처음 확인하는 순서 (프롭을 떼고)

1. **RAM 으로 한 대**: 4장의 `load_tag.py` 로 올리고, USB 기록에 `TF_INFO,...,flight=1`, `TF_SD,ready=1,...,file=ok`, `E,0,flight_uart,1,...` 이 나오는지 봅니다.
2. **중계**: 드론 배터리를 연결하고 `n6_fly.py --no-arm` 으로 붙어, 전과 같이 상태줄(모드, 높이, 거리센서)이 나오는지 봅니다. USB 기록에 `E,...,fc_seen` 과 `U` 줄(오류 0)이 나와야 합니다.
3. **외부 플래시**: 1, 2가 되면 4장대로 쓰고 비행 모드로 켜서 2를 다시 봅니다.
4. **앵커와 함께**: 앵커 3대(대본 없는 판)를 켜고 SD 기록을 꺼내 `F`, `R`, `P`, `C` 줄이 있는지 봅니다.
5. **대본, 프롭 없이**: 앵커 1 을 `s1v30` 으로 바꾸고, 프롭을 뗀 채 시동·GUIDED 상태를 만들 수 있으면 대본의 `E,start`, `C` 줄의 명령, `E,done` 을 봅니다. 조종기 스위치로 모드를 바꿔 `E,abort_mode` 가 나오는지도 봅니다.
6. 그다음에 한 대 비행, 여섯 대 비행.

## 7. 확인한 것과 안 한 것

확인한 것 (PC)
- 컴파일: CubeIDE Debug 구성 `-O2`, 오류 0, 경고 0. 코드 110 kB, 변수 88 kB (한도 255 kB, 256 kB).
- `tag/test_fcl.py` 55개 통과: 가짜 비행 제어기와 가짜 노트북(pymavlink)으로
  - 중계가 바이트 그대로인지(끊겨 들어오는 경우, 쓰레기가 끼는 경우, MAVLink 1 포함)
  - 보드가 만든 속도 명령을 pymavlink 가 그대로 읽는지(기체 기준 8, 무시 표시 0x5C7, 속도 값)
  - 대본 1 의 줄이 바뀌는 프레임과 값, 10 Hz, 끝난 뒤 속도 0 다섯 번
  - 3장의 안전 규칙 전부
- 서명 도구가 머리를 붙인 파일을 냄(파일만 만듦, 보드에는 쓰지 않음).

안 한 것
- **실제 보드에서의 실행 전부**: UART 인터럽트(`flight.c`), 외부 플래시 부팅, SD 와 무선과 UART 가 같이 도는 것.
- **실제 ArduCopter 가 이 속도 명령에 어떻게 움직이는지.** 광류로 GUIDED 속도 제어가 되는지, 기체 기준으로 도는지, 기수 방향이 유지되는지는 띄워 봐야 압니다.
- 보드가 요청한 50 Hz 위치 값 때문에 BLE 쪽이 밀리지 않는지(노트북으로는 5 Hz 로 줄여 넘기지만 실제로 확인하지 않음).
- `GUID_TIMEOUT` 의 실제 동작.

## 8. 알아 둘 점

- **대본 비행에는 `n6_fly.py --hover-key` 를 씁니다**(이 묶음의 `n6_fly/n6_fly.py`, 11-24 밤에 더함). 이륙한 뒤 `l` 키를 누를 때까지 호버하고, 누르면 정상 착륙 순서로 내립니다. 안 누르면 `--hover-max`(기본 300초) 뒤에 스스로 착륙합니다. 킬(스페이스)과 모드가 바뀌면 중단하는 동작은 그대로입니다. `--hover`(정해진 시간, 30초까지)로는 대본 도중에 착륙하게 됩니다. 오프라인 시뮬레이터 57/57 통과, 실제 기체로는 안 해 봄.
- `n6_fly.py` 는 한 번에 한 대에 붙습니다. 여섯 대를 같이 띄우는 도구는 만들지 않았습니다.
- 앵커 1 이 꺼져 있으면 태그는 프레임을 모릅니다. 그동안에도 BLE 중계와 SD 기록(비행 제어기 값은 프레임이 있어야 남음)은 돕니다.
- 비행용 빌드의 USB 출력(USART1)은 비행 중에는 연결돼 있지 않습니다. 기록은 SD 가 주입니다.
